# ADLabs GovFlow — Stage 0 + Stage 1

Учебная компания CivicTech Solutions обрабатывает синтетические заявления на разрешение. Цель: воспроизводимый QA-стенд с доказуемыми инвариантами, а не государственная система. Подписи — только HMAC-симуляция, не ЭЦП и не NCALayer.

Реализуемая граница: один FastAPI, PostgreSQL, Alembic, React/TypeScript; вход, роли, tenant, заявления, вложения, ревизии, две подписи, аудит, детерминированная локальная проверка. Registry HTTP, брокер, надёжная доставка, Fault Engine, mutants, WorkLab и виртуальное SLA относятся к следующим этапам. Их наличие не заявляется.

## Пять пользовательских процессов

1. Applicant создаёт черновик, загружает синтетический PDF/PNG, готовит и подписывает, отправляет; локальная проверка передаёт reviewer, reviewer одобряет, officer подписывает решение → COMPLETED.
2. Reviewer возвращает на исправление с причиной; applicant редактирует, подписывает новую ревизию и повторно отправляет.
3. Reviewer отклоняет с основанием → REJECTED; последующие команды отклоняются.
4. Applicant отменяет DRAFT/NEEDS_CORRECTION → CANCELLED.
5. QA проверяет tenant B против UUID tenant A, stale version, повтор submit и неверный хеш; состояние не изменяется при отказе.

Пользователи, организации, файлы и данные исключительно синтетические. Новый seed создаёт стабильные UUID для каждой роли/tenant; пароль генерируется локально, не хранится в репозитории.
